# bleu_wl

A pure-C3 Wayland client: the wire format, a display connection with an object
table and dispatch, a client with registry and globals, and the protocol bindings
generated from the protocol XML. No libwayland. Module root `bleu::wl`.
Depends on `bleu_core` and `bleu_rt`. Sources and decisions: `docs/research/bleu_wl.md`.

Linux, BSD and macOS use the Unix socket layer of `bleu::rt`. Windows type-checks
and `Client.connect` raises UNSUPPORTED (Wayland has no Windows back end).

## Public API (summary)

* `bleu::wl::wire` - framing and arguments, platform-neutral. `Writer` (`begin`,
  `put_*`, `finish`), `Reader` (`get_*`, `expect_end`), `read_frame(bytes) -> Frame`
  (`complete`, `size`), `FdQueue`, `Fixed` (24.8, `to_double`, `fixed_from_double`).
* `bleu::wl::display` - `Display`: `adopt(alloc, fd, root_interface)`, `close`,
  `native` (poll on it), `set_nonblocking`, `flush` (true when drained), `dispatch`
  (returns messages handled), `new_object`, `server_object`, `find`, `retire`,
  `release_id`, `send`. `Proxy` and `Interface` (name, version, dispatch) are what
  generated code is written against.
* `bleu::wl::Client` - `connect(alloc, path)`, `connect_env(alloc)` (POSIX:
  `WAYLAND_SOCKET`, then `WAYLAND_DISPLAY` under `XDG_RUNTIME_DIR`), `init(alloc, fd)`,
  `close`, `roundtrip` (blocking descriptor only), `bind(global, iface) -> Proxy*`
  (version = min of the two), `globals_view`, `set_listener(ClientListener)` (global
  added and removed), `flush`, `dispatch`, `native`.
* `bleu::wl::proto::<module>` - generated: per interface a `WL_*` constant
  (`display::Interface`), a typed view struct `Wl*`/`Zwlr*`/`Ext*` (the proxy is its
  first field), `constset`s for enums, a `*Listener` struct of function pointers
  (`void* context` first), request methods, `set_listener`, `destroy`.

### How to add a protocol

1. Add a line to `tools/wlscan/protocols.tsv`: the C3 module name (lower snake case,
   at most 31 characters) and the raw URL of the XML.
2. Run `tools/wlscan/regen.sh` (or `WLSCAN_XML_DIR=dir tools/wlscan/regen.sh` with the
   XML already downloaded, named `<module>.xml`). It writes `src/proto/<module>.c3`
   and runs `c3fmt`.
3. Run `tools/check.sh bleu_core bleu_rt bleu_wl`, and commit the generated file.
4. To use it, write a `Client` listener struct for the interface and bind the global.
   A generated module that references another protocol's interface imports it
   automatically.

Generator behaviour: an untyped `new_id` (only `wl_registry.bind`) takes the interface
name and version on the wire; typed `new_id`s are returned by the request. Destructor
requests and events retire the object locally. `wl_display.error` and `delete_id` also
call the runtime. Requests with `since` above the bound version fail with UNSUPPORTED.

## Not done

* Only Linux has run; the Windows and macOS builds are type-checked only, and
  `Client.connect` raises UNSUPPORTED there.
* Against a real compositor only the core globals were exercised (headless weston
  13.0.0: registry, `wl_output`, roundtrip). The wlroots and ext protocols in the
  table are tested against the in-process mock only. Weston 13 does not advertise
  gamma control, output management or data control, so they could not be tried there.
* The poller path (`native` in a `bleu::rt::poller`, then `dispatch`/`flush` on
  readiness) is exposed but no test drives it. `roundtrip` needs a blocking descriptor.
* Events from the server for an unknown object id are a protocol error, but an object
  argument that names an id the client no longer knows is passed to the listener as
  null. Enum values from the server are not range-checked.
* The object table is a list searched linearly; a client holds tens of objects.
* Big-endian hosts: the encoding is explicitly little-endian (all six targets are).
* No buffers, shm, surfaces or input handling: this is the control plane only.
* One message per `sendmsg`; descriptors are duplicated on `send` and closed after they
  are written.

## Verified how

* Unit (run, Linux x86-64, c3c 0.8.5, glibc): 13 `@test` functions in `src/wire_test.c3`.
  Golden bytes computed independently with Python's `struct` module (framing, padded
  strings, fixed, arrays, null string, `-1`); decoder rejections (no NUL, interior NUL,
  overrun, short and trailing data, malformed headers, bounded descriptor queue);
  20000 random buffers and 20000 mutated valid messages through the decoder, which
  must neither trap nor accept junk.
* End to end against the in-process `bleu::wl::testing::MockServer` (`src/mock_server_test.c3`),
  in `src/client_test.c3` (8 `@test` functions, 21 with the wire tests), the client on the test
  thread and the scenario on another:
  registry with add/remove listener, `delete_id` and sync-id reuse, `wl_output`
  geometry/mode/done with version negotiation (4 and 7), `ext_idle_notify` idled then
  resumed, gamma control with `gamma_size` and a pipe descriptor, output management's
  head, mode and done, then configuration with `apply` succeeded and server-created
  objects, data-control offer and `receive` through a pipe, and a `wl_display.error`
  that surfaces as PROTOCOL with the text in `error::last`.
* Real compositor: headless weston 13.0.0 from the Ubuntu package (fetched with
  `apt-get download` into a scratch directory, unpacked, run in a private mount
  namespace). A probe connected with `connect_env`, listed 16 globals, bound
  `wl_output` v4, received its mode (1024x640) and done, and completed a roundtrip.
* `tools/check.sh bleu_core bleu_rt bleu_wl`: clean on all six targets.
* `regen.sh` is deterministic: a second run over the same XML leaves the tree unchanged.
