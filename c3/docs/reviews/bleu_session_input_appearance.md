# Review of bleu_session, bleu_input and bleu_appearance

Reviewer pass against docs/REVIEW_CHECKLIST.md. One file for the three libraries, as requested. No library code was edited. Scratch programs live outside the repository.

**Verdict.**
bleu_session: the pure logic (idle registry, polled edges, conversions) is sound and its tests pass, but requests can hang forever when a worker stops, logind session discovery is never retried, and the macOS lock read reports "unlocked" for a key that is unverified.
bleu_input: one memory-safety defect (layout ids longer than 128 bytes overflow the fixed command buffer on the `next()` path, shown by a probe) and an event/publish ordering inversion; the Linux and Windows decoding and short-code logic is otherwise sound.
bleu_appearance: the Windows wallpaper request is unreachable (every `C:\` path is refused), Windows registry waits abort the process on OS errors, and a failed portal `Read` silently loses a change; the argv-only spawning and the portal variant handling are correct.

**Counts.** 26 defects: 4 HIGH, 9 MEDIUM, 13 LOW. 4 suspicions (unproven). One root-cause defect (X1) is in bleu_rt, outside the three libraries, and is counted once.

## Suspicions (unproven)

* **I6 (Windows, unverified).** `windows_klayout.c3:235-244`: the HKL is truncated to `uint` and posted back as `(long)wanted`, which zero-extends. HKLs with the high bit set may need sign extension on 64-bit Windows. Also, two HKLs with the same KLID value (`hkl.c3:40-47`) would give duplicate ids.
* **I8 (macOS, unverified).** `macos_tis.c3:146`: `CFDictionaryCreate` is called with NULL key and value callbacks. The usual idiom passes `&kCFTypeDictionaryKeyCallBacks` / `...ValueCallBacks`. Behaviour with NULL is not verified here.
* **I9 (unproven).** `names.c3:137-141`: two compositor layouts described the same way ("English (US)") map to the same id. `index_of` then returns the first for both, and `switch_to` picks the wrong one. Depends on what the compositor reports.
* **S9 (unproven).** `common_idle.c3:93` (`duration_of_seconds`): no upper clamp. A huge platform reading converts to `Duration` out of range. Also unknown: whether CoreGraphics returns a negative sentinel for "no event" (the code clamps negatives to zero, which would read as "active").

## What is good

* **Session.** Idle registry edges (`common_idle.c3`), polled record and settle logic (`common_polled.c3`, with the pending-scan rule), and the pure conversions are correct and covered by `common_test.c3`. Requests `Session.request` refuses by capability before queueing. `Connection.call` on a closed connection returns DISCONNECTED (`bleu_dbus/connection.c3:346`), so LOCK_SESSION after a disconnect does not touch freed state (checked, not a defect). The WTS lock mapping (`bleu_win/session.c3:20-23`, LOCK = 0) matches Learn. `IOAllowPowerChange` is sent for WILL_SLEEP (`bleu_objc/power.c3:399`).
* **Input.** HKL decoding matches the cited Learn and Wine rules (`hkl.c3`). The locale1 field splitting keeps variant alignment (`locale1_convert.c3`). Compositor switches are by id and resolved against the worker's current model (`linux_compositor.c3:242-258`), so a stale index from the caller cannot pick the wrong layout. TIS and Windows selection go by id. `fail_queued` runs on every `run` exit after the loop.
* **Appearance.** Spawning uses argv with no shell (`convert.c3:251-280`, `gnome.c3:104-119`, `desktop.c3:15-33`). The GVariant quoting and `file://` encoding escape `'` and `\` (`convert.c3:156-196`). The AppleScript is built from a boolean literal (`macos_appkit.c3:250`). Portal double-variant handling is right: the `Value` accessors unwrap every layer (`bleu_dbus/value.c3`), so `apply` and `accent_from_value` read the real values. `publish` emits after it publishes (`common.c3:43-59`). The Windows HKCU writes are limited to the personalize value (`windows_registry.c3:277-285`).
