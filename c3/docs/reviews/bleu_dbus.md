# Review of bleu_dbus

Verdict: not ready for services that rely on name ownership or on blocking calls.
Two defects are confirmed by running code against a private `dbus-daemon`: a name
granted at once fires `on_acquired` twice, and a closed connection leaves
`OwnedName.held == true` with `on_lost` never called. `process()` also aborts the whole
process on any non-EAGAIN `recvmsg` failure, and a handler error text that is not UTF-8
makes the server send no reply at all.
The wire-level code (marshalling, Reader bounds, signature and name grammar, auth
EXTERNAL, the Writer) is careful and held up under probing; the 81 existing unit tests pass.
Counts: CRITICAL 0, HIGH 2, MEDIUM 5, LOW 11.

Scope: every file in `libs/bleu_dbus.c3l/src/` and the unit tests were read. Integration
tests were not run (they need the full harness and a bus); see "Tests run and results".

## Suspicions (unproven)

* `marshal.c3:375-391` (`collect`), `value.c3:154, 188`, `address.c3:110`: each opens a `@pool()` and copies into the `Allocator` parameter. These are correct today, and I tested `read_value(tmem)`, `session_address(tmem)` and `dict_entry(tmem)` directly: the bytes survived churn and valgrind was clean. The reason is that `tmem` is an alias for the thread-local `current_temp`, evaluated at the call site, so the parameter still refers to the outer temp allocator. A refactor that evaluates `tmem` inside the pool would dangle silently. Recommend a comment at each site. I initially suspected these as defects and retracted that.
* The temp-pool dangling pattern in `server_builtin.c3:103` (`read_value(tmem)` for `Properties.Set`) is safe for the same reason, but the same fragility applies there.
* The `@pool` close in this stdlib build does not overwrite freed temp memory in any of my probes, so latent use-after-free would be invisible to these probes and valgrind.
* Handshake line length: I could not confirm a maximum for auth command lines in the spec text I read, so there is no finding on that. An unbounded line buffer during the handshake is bounded only by `HANDSHAKE_TIMEOUT_MS`.

## What is good

* Marshalling and the Reader are the strongest part. Every read checks the innermost container limit before touching a byte. Padding must be NUL. Strings are strict UTF-8 without NUL. Object paths, signatures and names are validated against the grammar. The depth limits (32 arrays, 32 structs, 255-byte signatures) are enforced at the signature level. The `Writer` validates before writing (apart from L4).
* `message.c3` checks the frame length before buffering (`frame_length`, 128 MiB cap), rejects serial 0, duplicate header fields, wrong header field types, a non-zero alignment pad, and a body length that disagrees with the frame.
* `transport_posix.c3` gets the `msghdr`, `cmsghdr` and `sockaddr_un` layouts right for both Linux and Apple, with cited sources. Descriptor passing is correctly tied to the first byte of a message on send.
* Server routing is well ordered: standard interfaces first, then the object, then the method. Signatures are checked against the declared in-signature. Handlers are checked once at export (`validate_interface`). A reply to a call sent with NO_REPLY_EXPECTED is suppressed. A reply whose body fails its out-signature is replaced by `Failed`. The answer is sent at most once through the `answered` flag. Deferred replies after a disconnect return DISCONNECTED and do not crash.
* `expire_calls` and `fail_pending` run handlers after the list is updated, and `deliver_reply` removes the entry before calling its handler. `deliver_signal` skips inactive subscriptions and frees them only between deliveries.
* Thread ownership is checked (in debug builds) for the main connection lifecycle methods, and handlers are not re-entered from the public `call`.

## Tests run and results

* Unit tests, `c3c --libdir "$(tools/libdir.sh)" --lib bleu_core --lib bleu_dbus compile-test libs/bleu_dbus.c3l/tests/unit/*.c3 -o <scratch>/testrun`, run from a private scratch directory: **81 passed, 0 failed, 0 skipped**.
* Integration (`tests/integration.sh`): not run in this review (needs the full private bus harness). Coverage gap: no integration test counts `on_acquired` calls, closes and reopens a connection, checks `on_lost` after disconnect, or sends a non-UTF-8 error text.
* Probes (scratch, not in `libs/`): `probe_own.c3` (H1, H2; run against a private `dbus-daemon`, two runs each), `probe_abort.c3` (M1), `probe_reply.c3` (M2), `probe_tmem.c3` (retracted suspicions: the values survived; valgrind reported no invalid reads). All in `<scratchpad>/dbus_review/probes/`.

* Not checked: the other five targets (`tools/check.sh`), the Windows and macOS compilation.

Every CRITICAL, HIGH, MEDIUM and LOW finding is FIXED. The status column says where a fix has
no test that can run, and why. "Before" is the library at commit 55ac8bf, the one this review
read; each regression test was run against it (10 of them fail there, see "Tests after the fixes").

* `bus.c3` `track_sender`: the swallowed `GetNameOwner` failure now has a comment saying why the owner stays unknown.
* `bus.c3` `subscribe`: if `track_sender` fails after `AddMatch` succeeded, the match is removed again and the rule freed (was: leaked, and the bus kept sending).

## Tests after the fixes
