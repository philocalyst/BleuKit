# Review of bleu_media and bleu_notify

Verdict: The normal paths work. The MPRIS backend (36 of 36 live checks), the freedesktop notification server (44 of 44 live checks), the C3 sender and the unit tests (82 notify, 21 media) all pass, and both libraries type-check on all six targets.
The notification server is not safe to expose to every local app as written. Any local process can overwrite or close other apps' notifications (CRITICAL ones included), take over org.freedesktop.Notifications with one call and read every notification, make two open notifications share an id, and make the centre retain about one message's size per notification. The macOS sender has a probable use-after-free when the permission prompt goes unanswered for 60 s (code path only).
The media side has contract drift (it publishes every second while playing), a parser that silently drops a player whose title contains a tab, peer-controlled rates and timestamps that extrapolate to absurd positions, and Windows and macOS error paths that hide failures. Windows and macOS code was type-checked only, never run.

Count: 0 CRITICAL, 5 HIGH, 14 MEDIUM, 7 LOW.

Scope: every file under `libs/bleu_media.c3l/src/` (incl. `tests/run.sh`, `tests/mock_players.py`, `tests/live/main.c3`) and `libs/bleu_notify.c3l/src/` (incl. `tests/`), their READMEs and manifests. Cross-checked against `libs/bleu_service.c3l/src/hub.c3`, `libs/bleu_rt.c3l/src/mailbox.c3` and `worker.c3`, `libs/bleu_dbus.c3l/src/{connection,server,server_call,bus,transport_posix,message}.c3`, `libs/bleu_win.c3l/src/winrt.c3`, `libs/bleu_objc.c3l/src/applescript.c3`, and the docs ARCHITECTURE.md, STYLE.md, SERVICE_TEMPLATE.md, C3_GOTCHAS.md.

Revision: reviewed at 80d8999 plus the working tree. HEAD moved during the review to 4545758, which adds `Hub.abandon` (438acfb, bleu_service) and closes the mailbox when a worker's run returns (4545758, bleu_rt). Neither commit changes a line of bleu_media or bleu_notify. M-01 reflects the new hub API.

Requested items, where they are covered:
* MPRIS discovery and NameOwnerChanged races: no defect proven; see S-6 and S-7, and "What is good".
* Position extrapolation and clamping: M-04, M-05; the clamp itself is correct (What is good).
* Active-player policy: correct and deterministic (What is good).
* SetPosition track check: correct for ids (What is good); L-05 for trackless and scripted paths.
* SMTC vtable slots, IIDs, enum values, apartment: all verified against windows-rs 0.62.2; M-07, M-08, L-02, L-03.
* AppleScript parsing and injection: no injection path exists (What is good); M-03 is a parsing defect, M-09 a blocking one.
* Notify image validation, markup, unbounded input, ids, expiry, history, DND, name takeover, macOS bundle check: N-01 to N-12 and M-series as listed.

## Suspicions (unproven)

* S-1 Span text: `markup.c3:198-210` decodes `&lt;` into a literal `<` inside `Span.text`. A shell that renders span text as Pango markup would inject markup. The `Span` doc should say "plain text, never markup".
* S-2 `image_path`, `app_icon`, `sound_file` and `Span.link` are untrusted paths and URLs. Nothing in the model says the shell must not open or play them; the consumer needs a policy.
* S-3 macOS: UNUserNotificationCenter may deliver its completion on the main queue. If the caller is the main thread, `authorize` (`sender_un.c3:124-146`) blocks for 60 s and then reports PERMISSION_DENIED. Needs a Mac to confirm.
* S-4 Scripting: the first-run Automation prompt blocks the worker for as long as the user takes (see M-09). Not measured.
* S-5 bleu_dbus `connection.c3:353` and `:487`: `read_available(c)!!` aborts on any recv error other than EAGAIN, EINTR, ECONNRESET and EOF (`transport_posix.c3:276-285` maps other errors to `failure`). It sits under the blocking calls that media and notify use. Owned by bleu_dbus; flagged here because it turns a transport error into an abort.
* S-6 `mpris_backend.c3:119-122`: a poller error other than TIMEOUT ends the loop with no error state. Whether bleu_rt's poller reports EINTR as an error was not checked.
* S-7 MPRIS owner change: a player that exits and whose name is retaken before the next reconcile keeps its record and handle (`mpris_session.c3:139-150`, `:191-214`). Re-reads are driven by the dirty flag, so it should self-correct; not tested.
* S-8 GetCapabilities advertises body-markup while the sender sends a raw body (N-08).

## What is good

* Image validation (`hints.c3:172-232`): depth 8, dimensions up to 4 096, channel count matching the alpha flag, stride range, and a 512 KiB budget. An invalid image is dropped and counted, never shown. `hints_test` fuzzes this for 20 000 rounds.
* Markup output carries no tag passthrough: unknown tags are removed, entities are limited to the five named ones, and the run count is capped (`markup.c3:105`).
* `text::truncate` (`text.c3:10-17`) cuts on UTF-8 boundaries.
* Wire limits (`wire.c3:33-87`): string lengths capped, timeout clamped to -1 through one day, actions paired, de-duplicated and capped.
* A bus handler's failure becomes a D-Bus error reply (`bleu_dbus server.c3:271-287`), so a malformed Notify cannot abort the server.
* Expiry against close is race-free: one worker, and `store.close()` decides, so nothing is announced twice (`fdo_commands.c3:28-33`). A replaced id's timer is cancelled before the new one is scheduled (`fdo_methods.c3:76-81`), so `schedule(...)!!` holds its invariant.
* Ids: 0 is never issued (`rules.c3:23-27`), though the collision in N-01 is not handled.
* Name loss publishes `serving=0` and refuses queued commands (`fdo_commands.c3:21-25`, `:127-131`).
* Position: `position_at` clamps to [0, length] (`position.c3:46-47`). Active-player choice is deterministic (`policy.c3:83-106`). Controls are checked before any D-Bus call (`mpris_commands.c3:51`), so a refused control never reaches the player.
* SetPosition on a track with an id is refused if the track changed (`mpris_commands.c3:110-118`), and the live test confirms the stale call is never sent.
* AppleScript injection: none. Every `string::tformat` that builds a script takes only the `APPS` constants, integers, or fixed keywords (`scripting_backend.c3:151-179`, `:182-242`). No player-supplied text reaches a script.
* SMTC: the vtable slots used (IInspectable 0 to 5, then 6 to 24 as in the file), the statics IID `2050c4ee-11a0-57de-aed7-c97c70338245`, the session status values 0 to 5, the auto-repeat values 0 to 2, and the tick and epoch constants all match windows-rs 0.62.2 source (`src/Windows/Media/Control/mod.rs`, `src/Windows/Media/mod.rs`). The check was against the crate, not the author's comment.
* `Connection.unsubscribe` removes the local handler before it sends RemoveMatch (`bleu_dbus bus.c3:125-131`), so the swallowed RemoveMatch errors in `mpris_session.c3:117-121` and `:272-281` cannot leave a dangling callback. Checked and safe.
* `submit` reference counting (`media service.c3:207-220`, `notify service.c3:170-182`) is correct on the failure path.
* The macOS sender checks for a bundle identifier before any UserNotifications call (`sender_un.c3:74-82`), and unsupported features are refused, not dropped (`sender.c3:133-150`, `sender_toast.c3`).
