# Review of bleu_objc

Verdict: No ABI-level defect was found. The struct layouts, constants, message-send variants and BOOL encodings all match Apple's headers and the clang and libclosure sources. The six targets type-check clean.
The defects are in error classification and silent failure (a NULL power-source list reads as "no batteries"), shutdown ordering in `RunLoopThread`, a `kIOMainPortDefault` link that needs macOS 12, and one `@pool()` lifetime contract violation in `run_script` that two callers hit.
Count: 0 CRITICAL, 0 HIGH, 4 MEDIUM, 13 LOW. Resolution pass: R-01 to R-13, R-15 and R-17 FIXED (R-13 in part); R-14 and R-16 WONTFIX with reasons; R-18 added (MEDIUM, the R-01 pattern in two more functions) and FIXED. See the Resolution section. Nothing could be executed (Darwin only); the MEDIUM items are proven by code path, and R-01 was also probed on Linux with a mirror of its pattern.

Scope: every file under `libs/bleu_objc.c3l/src/` (2 730 lines incl. README and manifest), the README, `docs/research/bleu_objc.md`, and the callers in `libs/bleu_battery`, `libs/bleu_session`, `libs/bleu_appearance`, `libs/bleu_media`, `libs/bleu_apps`, `libs/bleu_windows`. Line numbers are the current file.

## Suspicions (unproven)

S-1 to S-9 were not addressed in this pass. Each is still unverified.

* **S-1 `from_string` returns nil on invalid UTF-8** (`foundation.c3:81-87`, `cf.c3:140-142`). Both bindings return nil (no error) when the bytes are not valid UTF-8, which I expect from the Apple docs, but I did not fetch that text. A caller then passes nil on. The concrete path is `libs/bleu_apps.c3l/src/darwin_launch.c3:84-86`: a nil from `from_string(argument)` goes to `addObject:`, which raises NSInvalidArgumentException. Check the Apple doc, then return `INVALID_ARGUMENT` on nil.
* **S-2 `BlockSubscription.close` does not wait for an in-flight handler** (`notify.c3:105-111`). `removeObserver:` stops future deliveries, but a delivery already running on another thread can still read `user` after `close()` returns. The appearance caller passes `&hub.worker.mailbox` (`macos_appkit.c3:93`), which outlives `run`, so it is safe in practice. Not verified against Apple's guarantee.
* **S-3 `com.apple.screenIsLocked` is unverified** (`notify.c3:46-50`). I found no primary source for it. Left as the research record states.
* **S-4 `AppleInterfaceThemeChangedNotification` has one source** (tao, research row 117). Not checked further.
* **S-5 NSAppleScript on worker threads** (`applescript.c3:39`, called from service workers in `bleu_media` and `bleu_appearance`). I did not verify NSAppleScript's thread affinity.
* **S-6 Per-callback arena** (`runtime.c3:144`, `:159-167`). Every block and observer callback allocates a 256 KiB temp arena via `@pool_init`. Cost not measured.
* **S-7 IOKit notification refcon lifetime** (`iokit.c3:219-277`). The header does not say whether callbacks can run after the notification object is released. `on_matching` and `on_service_change` have no callers, so the question is latent. The lib's `NotificationPort.close` does not order callbacks against refcon teardown.
* **S-8 BOOL encoding and the research record.** Resolved: confirmed (see "What is good"). Row 37 should cite clang, not only an objc2 comment.
* **S-9 `SleepAssertion` copies** (`power.c3:274-303`). The struct is copyable and `release` is idempotent per copy, so two copies that each release will both call `IOPMAssertionRelease` on the same ID.
* **S-10 Restart after failure** (`runloop.c3:103-105`): FIXED with R-08.

## What is good

* **Constants and layouts checked against primary sources, all match.** errno values (`errno.h`), KERN_* (`kern_return.h`), every `IO_*` code in `mach.c3` against `IOReturn.h:141-197`, all `MSG_*` against `IOMessage.h` (`0x250`, `0x270`, `0x280`, `0x290`, `0x300`, `0x310`, `0x320`), `kCFNumberSInt64Type = 4` and `kCFNumberDoubleType = 13` (`CFNumber.h:54,64`), `kCFStringEncodingUTF8 = 0x08000100`, the CFRunLoopSourceContext field order (`CFRunLoop.h:108-118`), the Block flag bits (`Block_private.h`, `BLOCK_HAS_COPY_DISPOSE = 1 << 25`), the descriptor layout (`Block_descriptor_1` `reserved, size`; `Block_descriptor_2` adds copy and dispose), the IOPS and IOPM keys and values (`IOPSKeys.h`, `IOPMLib.h:292, 433`), NSUTF8StringEncoding, and the CocoaError codes (`objc2-foundation-0.2.2` `FoundationErrors.rs`, `NSString.rs:40`).
* **Message-send variants.** The stdlib `send` macro (`/opt/c3/c3/lib/std/os/darwin/objc.c3:137-141`) uses `objc_msgSend_stret` only for non-arm64 returns above 16 bytes. `objc-msg-arm64.s` has no `objc_msgSend_stret` (`:790`). `NSRange` (16 bytes) and `CGRect` (HFA on arm64, stret on x86_64) match. The typed function-pointer cast is the non-variadic form, which is the correct arm64 convention for `objc_msgSend`.
* **BOOL encodings `B` and `c` are right, now with a primary source.** clang sets `__OBJC_BOOL_IS_BOOL` from `useSignedCharForObjCBool()` (`clang/lib/Frontend/InitPreprocessor.cpp:998-999`). The default is true (`clang/lib/Basic/TargetInfo.cpp:152`). `DarwinAArch64TargetInfo` clears it (`clang/lib/Basic/Targets/AArch64.cpp:1915`), so arm64 BOOL is `_Bool` (`B`). Darwin x86_64 keeps the default (signed char, `c`). The objc4 `objc.h` branch (`:68-88`) agrees.
* **Retain/release balance on the block path.** `make_block` (`block.c3:195-211`) starts the context at 1, the copy helper adds 1, and the creator's `sub(1)` returns 2 and does not free. The dispose helper's `sub(1)` returns 1 and frees. Each path is balanced for copy success and for copy failure (`block_copy_raw` returning NULL leaves the count at 1, which the creator frees).
* **Ownership discipline.** `Obj` and `cf::Ref` make the adopt/borrow choice explicit, and `close()` is idempotent. `defer` follows each acquire at the sites I checked (`cf.c3:160-173`, `iokit.c3:129-130`, `power.c3:182-191`, `applescript.c3:45-49`, `dispatch.c3:151-159`).
* **CF and IOKit ownership.** `IOServiceGetMatchingServices` and `IOServiceAddMatchingNotification` consume the matching dictionary, and the code does not release it (`iokit.c3:156, 228`; `IOKitLib.h:438`). `IOPSGetPowerSourceDescription` is a Get-rule value and is not released (`power.c3:197`). The Create and Copy results are adopted (`power.c3:182, 190, 240, 254, 261`). `CFRelease`/`IOObjectRelease` run on every path I checked.
* **Power teardown order.** `SystemPower.close` runs `IODeregisterForSystemPower`, then `IOServiceClose(root)`, then destroys the port, then frees (`power.c3:366-372`). That order matches the Apple sample and `IOPMLib.h:192-200`. `IOAllowPowerChange` uses the root port and the message argument as the notification ID (`:399`), which is correct for `CanSystemSleep` and `WillSleep`.
* **Callback discipline in callers.** The battery notifier only enqueues (`libs/bleu_battery.c3l/src/macos_iokit.c3:120-127`), and `run_loop_perform` checks `stop_requested` before running the handler (`runloop.c3:167`).
* **Error mapping, mostly sound.** `classify_ns_error` maps TCC and AppleEvents refusal to `PERMISSION_DENIED` with `errAEEventNotPermitted = -1743` (`objc2-core-services` source, research row 113). `NSCocoaErrorDomain` values match. The POSIX errno codes match `errno.h`.
* **Header-accurate documentation.** The `@return` contracts in most of the public functions match the code paths, and the README "Not done" list is accurate.
