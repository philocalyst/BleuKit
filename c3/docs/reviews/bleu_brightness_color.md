# Review of bleu_brightness and bleu_color

Reviewed at HEAD 80d8999 with the working-tree changes to other libraries left as found. No library code was edited. Scratch programs live outside the repository (see "Tests run").

## Verdict

**Status after this pass: all findings are fixed, marked WONTFIX with a reason, or PARTIAL (B6, B10, S2 in part). Each finding has a status in the table.** The verdict below is the review as it was found; the status column is the outcome.

- **bleu_brightness: NOT ACCEPTED as-is.** The request policy, the executor and the transition engine are sound, and the suite passes (139 unit and fake-root tests, plus the logind route in both stand-in modes). Two defects block use by a shell: `DdcDisplay.detach` closes fd 0 on the injected-bus path (B1), and a request can wait forever when a backend's worker has already returned (S1). The writable flag and the write-success contract (B2, B4) also overstate what the device did.
- **bleu_color: NOT ACCEPTED as-is.** The Kelvin table is identical to Redshift's 242 rows, the ramp maths matches Redshift's `colorramp_fill_float`, the NOAA schedule agrees with NOAA's own `main.js` to within 36 s, and the wlr descriptor lifetime is correct. Blocking: the schedule is discontinuous when two edges fall inside one transition (C1), and NaN requests are accepted and silently turned into 0% or 1000 K (S2). S1 applies here too.
- **Counts: 2 HIGH, 10 MEDIUM, 25 LOW** (37 defects, both libraries and shared infrastructure). Suspicions (unproven) are listed separately.

## Answers to the brief

- **Can a software result silently replace an EXACT or hardware request?** No, in the code as written. `candidates()` returns nothing for EXACT when the named control is not writable, and `refusal()` reports why (`libs/bleu_brightness.c3l/src/policy.c3:30-37`). PREFER_HARDWARE reaches software only when the last snapshot has no writable hardware control (`policy.c3:40`), and `Applied.mechanism` names the mechanism that wrote. No backend in this library produces a software control at all (`linux_driver.c3:53-60`, `windows_driver.c3`, `macos_driver.c3`), so that path cannot be reached today; it becomes live with a GAMMA backend, and then depends on the stale `writable` flags of the last snapshot.
- **Transition engine races.** Cancel-on-new-request and shutdown cancellation are correct (`libs/bleu_brightness.c3l/src/engine.c3:194-201`, `272-283`; tests `engine_test.c3:197-243`). Two issues: a ramp that cannot read a starting level jumps instead of ramping (B13), and transients are announced before the state they describe is published (S3).
- **Write verification and read-back.** No path compares read-back with the requested value. Every backend returns success on any write that did not raise (B4).
- **sysfs selection priority.** Correct. `type_rank` gives firmware 3, platform 2, raw 1 (`sysfs_convert.c3:19-28`), which matches the kernel ABI text ("firmware control should be preferred to platform control should be preferred to raw control", `Documentation/ABI/stable/sysfs-class-backlight`, fetched). Ties resolve by name.
- **i2c ioctl/flock and bus-open failure paths.** Constants and the ioctl sequence are right (`linux_i2c.c3:18-28`, `66-86`), and errno is captured before `close`. Defects: the lock is held for the display's lifetime (B5), bus-open failures are mapped to the wrong availability class (B6), and the injected-bus path closes fd 0 (B1).
- **logind SetBrightness fallback.** The call matches systemd's `logind-session-dbus.c` (`SD_BUS_ARGS("s", subsystem, "s", name, "u", brightness)` at line 1086; subsystem gate at 686-687; "no seat" and "not in foreground" refusals at 691-694). The fallback itself is silent (B11), can stall the worker (B3), and the `writable` flag ignores whether logind will accept (B2).
- **macOS private DisplayServices gating.** Presence is gated correctly: symbols are bound by `dl`, a missing one gives `BACKEND_MISSING`, and status 0 is success (`macos_displayservices_private.c3:48-53`, `macos_driver.c3:82-92`). The file's own header says "NOT RUN". Gating checks presence only, not signatures (U6).
- **Gamma ramp maths.** Correct against Redshift (see "What is good"). NaN handling is wrong (S2). The 16-bit encoding rounds to nearest with full scale 65535 and is clamped (`ramp.c3:76-94`). Ramp sizes are right per backend: wlr from `gamma_size`, Windows 256, CoreGraphics from the sample count (with an unverified capacity assumption, U1).
- **wlr-gamma fd lifetime and lost-control path.** The descriptor is safe. `bleu_wl` duplicates each descriptor when the request is queued (`libs/bleu_wl.c3l/src/display.c3:278-283`), so closing the memfd after `set_gamma` is correct. The lost-control path works (`release_lost` at `linux_wlr.c3:434-444`), with ordering issues (C6, C7).
- **Schedule maths vs NOAA.** Matches. Details under "What is good". The overlap discontinuity is C1.

## Suspicions (unproven)

- **U1. CoreGraphics table capacity** (`coregraphics.c3:43`, `119-131`). The backend reads at most 256 samples and treats the count as the table size. It never queries the display's table capacity (CoreGraphics has `CGDisplayGammaTableCapacity`; not checked here). A display with a larger table would be captured truncated, and `release_ramp` would write the truncated table until shutdown. Not run.
- **U2. Ramp persistence after a crash.** On macOS and Windows, a process that dies while a ramp is set may leave the display altered, since neither backend restores on abnormal exit. Not run.
- **U3. DDC ramp overrun.** Each ramp step performs a set and a read-back (`linux_ddc.c3:136-141`), then `publish` re-reads every display (`engine.c3:81-105`, `step_ramp` publishes every step). That is about three DDC transactions per 100 ms step, and DDC needs tens of milliseconds between transactions. The steps may overrun. Not measured.
- **U4. Mixed polar days.** When a neighbouring day has no crossing, the level before the first edge is inferred from that edge (`schedule.c3:212`). This could be wrong at polar transitions. Not reproduced.
- **U5. TIMES offset for neighbouring days.** The local midnight for days -1, 0 and +1 uses the UTC offset in effect at `now` (`schedule.c3:202`). Across a DST change this would shift edges by an hour for the window before the change. I could not construct a case where the shifted edge affects the output, because edges after the change are recomputed once `now` passes it. Not reproduced.
- **U6. Private DisplayServices signatures.** The gating checks symbol presence only. A changed signature would be a crash, not a refusal. The file says "NOT RUN", which is correct.
- **U7. Late `failed` on a destroyed control.** `release_lost` destroys a control and resets `failed`, but a `failed` event for the destroyed object may still arrive. It is only harmless if `bleu_wl` drops events for retired ids; not checked.
- **U8. Windows read-back tolerance.** `READBACK_TOLERANCE = 256` (`windows_ramp.c3:35-36`) is an assumption, and the file says so. Unverified on hardware.
- **U9. Windows panel AC scale.** `PANEL_STEPS = 100` (`windows_panel.c3:36`) is an assumption, and the file says so. Unverified.
- **U10. Linux flock and logind on real hardware.** The i2c locking behaviour (B5) and the foreground rules (B2) were established by reading. No i2c adapter or real logind seat was available.

## What is good

- **Policy semantics** are implemented as documented: EXACT never redirects; ALLOW_SOFTWARE falls back only on hardware failure; `Applied.mechanism` names what wrote (`policy.c3`, `apply.c3`). Tests cover prefer, allow, exact-refused and hardware-failure cases (`engine_test.c3:123-186`).
- **Transitions** cancel on a new request and finish with `CANCELLED` on shutdown (`libs/bleu_brightness.c3l/src/engine.c3:194-201`, `272-283`), with tests (`engine_test.c3:197-243`).
- **sysfs ranking** matches the kernel ABI (firmware, platform, raw), with a deterministic tie-break by name (`sysfs_convert.c3:19-52`).
- **logind call** matches systemd: the signature `(s, s, u)` on the caller's own session, the subsystem gate, and the seat and foreground refusals (`linux_logind.c3:36-49`).
- **i2c open** uses the right flags and constants (`O_CLOEXEC`, `I2C_SLAVE`, `LOCK_EX|LOCK_NB`, `EWOULDBLOCK`), closes the descriptor on each failure path, and captures errno before `close`.
- **macOS DisplayServices** is resolved at run time, and a missing symbol becomes `BACKEND_MISSING` at open, not a load failure (`macos_driver.c3:82-92`).
- **Kelvin table**: all 726 values match Redshift's `blackbody_color` (242 rows), with zero mismatches (checked by script on the fetched `redshift/src/colorramp.c`). 6500 K is exactly (1, 1, 1). Interpolation matches Redshift's `alpha = (temp % 100) / 100` and the clamp.
- **Gamma maths**: `ramp::fill` computes `pow(x * brightness * white, 1/gamma)`, the same as Redshift's `colorramp_fill_float`; the identity ramp is linear; entry i answers i/(size-1).
- **wlr-gamma**: the fd holds three tables of `gamma_size` 16-bit words, which matches the protocol text; `destroy` restores the table; the memfd is written with `pwrite` at offset 0; the descriptor is closed after the send is queued, and `bleu_wl` duplicates it at queue time.
- **Schedule vs NOAA**: every function in `schedule.c3` corresponds to the NOAA `main.js` function it cites (`calcGeomMeanLongSun` through `calcEquationOfTime`, `calcHourAngleSunrise` with 90.833). Against NOAA's own code run in Node, `day_events` differs by at most 36.2 s (Anchorage sunset, 2026-10-20: 36.2 s; London sunrise, 2026-03-20: -34.6 s; Sydney sunrise +11.7 s). Polar days and nights agree exactly (NaN in NOAA is `NOCROSS` here). The residual comes from evaluating the sun at solar noon rather than at the event, which is consistent with the stated "about a minute".
- **Windows ramp** reads back after each write and captures the original ramp for restore. `DISPLAY_DEVICE_SIZE` (840) and `DISPLAY_BRIGHTNESS` (3 bytes) match the struct layouts cited.
- **Tests**: the brightness suite covers the logind route in both stand-in modes, and the color wlr tests run the full protocol exchange against the in-process mock.
