# Review of bleu_compositor and bleu_windows

Verdict: the socket framing, the hostile-JSON handling, the id checks, the Alt-Tab predicate and the Win32/COM bindings hold up on the paths read. The six-target check and both live suites are clean.
Two defects matter most: sway and i3 snapshots mark every tiled window as floating (a fixture hides it), and any worker that exits early leaves queued actions uncompleted with the mailbox still open, so waiters hang.
Incremental updates leave output state stale, the reconnect timer restarts on every wakeup, and blocking command sockets have no timeout, so a silent compositor can hang the worker and `close()`.

Evidence key: **RUN** = reproduced by a scratch program or an existing test run; **PATH** = precise code path, not executed (no Windows or macOS host here, and the failure cannot be injected on Linux).

## Suspicions (unproven)

* **S-1** `IVirtualDesktopManager::MoveWindowToDesktop` may only work on windows the calling process owns. The README calls the call "documented". The fetched Microsoft page had no Remarks section, so this could not be checked (`win32_vdm.c3:79-83`).
* **S-2** `Windows.close()` frees the service while another thread may still be inside `send_request` (`service.c3:63-70`). The header says "any thread". Either make `close` exclusive or document that it must not overlap calls.
* **S-3** macOS observer: `on_activate` reads the module global `active_hub` from the notification thread, while the worker writes it (`macos_workspace.c3:226-245`). A block may post after `watch.close()` if `removeObserver` does not wait for in-flight blocks. Then `Windows.close()` could free the hub under it. Needs `bleu_objc` `notify::BlockSubscription.close` semantics, which were not read.
* **S-4** sway command lists are split on `;` and `,` (`sway/commands.c:254`, `argsep(&head, ";,", ...)`). Quote awareness of `argsep` was not confirmed, because its source was not in the fetched files. `is_quotable` allows both characters. Workspace names come from the user's own compositor, so impact is low.
* **S-5** niri `WindowOpenedOrChanged` with `is_focused=true` does not clear the previous focus flag (`niri.c3:318-335`). This relies on a following `WindowFocusChanged`. The niri event order was not checked.
* **S-6** i3 was not checked against its own source. The shared snapshot code path is the same as sway's.
* **S-7** Linux `Link.act` maps a connect failure to a non-DISCONNECTED error. The connection then stays marked connected until the event socket reports EOF (`linux_compositor.c3:255-273`).
* **S-8** The Windows backend uses MTA for `IVirtualDesktopManager` (`win32_enum.c3:98`). Not checked against Microsoft's threading notes.

## What is good

* **Framing:** `wire.Buffer` refuses a unit over capacity with PROTOCOL and never grows (`wire.c3:107-117`). `take_line` and `peek_exact` handle partial reads and several units per read. `i3ipc.take_frame` checks the length before it waits for the payload (`i3ipc.c3:138-166`). The magic is checked.
* **Hostile JSON:** the std parser caps nesting at 64 (`std/encoding/json.c3:7`, `MAX_DEPTH_REACHED`, mapped to PROTOCOL). Every read goes through a type-checked accessor (`wire_json.c3`). Replies are capped at 16 MiB and event lines at 4 MiB (`io.c3:14-17`).
* **Id injection:** `is_token`, `is_decimal` and `is_quotable` are checked before each command is built (`wire.c3:163-199`).
* **Incremental apply:** the event socket is subscribed before the snapshot (`hyprland_io.c3:40`, `sway_io.c3:46-54`, `niri_io.c3:37-45`). Events are replayed on top of the snapshot. Most events carry absolute state (focus, floating, title, layout index) or are idempotent.
* **Connection lifecycle:** `drop` removes the poller source before closing the client. `run()` defers free the poller last. Backoff doubles on each failure and resets on success. REFRESH retries at once.
* **Operations on the normal path:** every backend's `run_command` completes and releases on all three paths (not connected, error, success): `linux_compositor.c3:255-273`, `win32_enum.c3:425-438`, `macos_workspace.c3:412-425`.
* **Alt-Tab predicate:** matches the cited Raymond Chen algorithm. The owner walk (`win32_enum.c3:315-326`) is equivalent to his pseudo-code. The tool-window and app-window rules match his text (saved copy checked). The rules are pure and tested.
* **WinEvent hook:** the callback filters and posts REFRESH only (`win32_enum.c3:189-206`). `active_hub` is cleared before `UnhookWinEvent`. The mailbox post is thread-safe.
* **Win32 bindings:** the win-event, GA, WS_EX and DWMWA constants match winuser.h and dwmapi.h values. The `IVirtualDesktopManager` vtable order after IUnknown (`IsWindowOnCurrentVirtualDesktop`, `GetWindowDesktopId`, `MoveWindowToDesktop`), the IID and the CLSID match the cited values.
* **macOS private gate:** `allow_private` defaults to false. SkyLight is bound at run time with `dl::bind` (`macos_spaces_private.c3:51-56`), with no link-time reference. CoreGraphics constants match the cited headers.
* **Mailbox:** `close` happens under the lock, so a post after close is refused. `take_all` runs under the lock and keeps the wake-up signalled when items remain.
