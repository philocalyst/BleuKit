# Review of bleu_audio

All paths are relative to `libs/bleu_audio.c3l/` unless they start with `docs/`.
Reviewer: adversarial review per `docs/REVIEW_CHECKLIST.md`. No library code was edited.

Verdict. The Linux `pulse` codec is well built: its tags, record layouts, version gates, command numbers and volume maths match PulseAudio master, and the mock and PipeWire 1.0.5 suites pass. Not ready to ship, though: one malformed reply blanks the whole service (A6), a hostile count aborts the process (A2), `close()` can hang (A5) or abort (A3), and `refresh()` does nothing on Linux (A4).
The Windows endpoint path frees one COM string twice on every enumeration (A1, code path only: there is no Windows host here), and the macOS and Windows backends were compiled but not executed.
Counts: 1 CRITICAL, 5 HIGH, 4 MEDIUM, 12 LOW. Fix A1 to A7 before any shell depends on this library.

## Suspicions (unproven)

* S1. `refresh_until_quiet` (src/linux_pulse.c3:167-173) loops while events keep arriving. A stream whose volume changes continuously could keep the worker in refresh and starve the command mailbox. Not triggered.
* S2. `absorb` and `read_frame` ignore `frame.channel`. A memblock frame (channel not -1) would be decoded as a command. Shared memory is never negotiated, so only a misbehaving server could send one.
* S3. Server strings are arbitrary bytes and are not checked as UTF-8. If they reach bleu_json unchecked, the JSON could be invalid. Not traced.
* S4. Proplist keys are checked for emptiness only. Upstream also rejects keys that fail `pa_proplist_key_valid` (src/pulsecore/tagstruct.c, proplist get). This decoder is more permissive.
* S5. `balance_of` sums `uint` values, so a hostile volume can wrap the sum. Upstream `get_avg` (src/pulse/volume.c:658-678) does the same. It affects only the derived balance.
* S6. Windows COM calls (EnumAudioEndpoints, Activate, the session enumerator) have no timeout. Cannot be tested here.
* S7. `unix::connect` on a full listen backlog may block the worker, and so may `open_session`. Not tested.

## What is good

* Tags, encoders and decoders agree with upstream master, field by field: `pa_tagstruct_put_*` in src/pulsecore/tagstruct.c (usec, format info, proplist, volume, sample spec, arbitrary, cvolume, channel map). The raw versus tagged bytes are right, including `write_u8` (raw) versus `pa_tagstruct_putu8` (tagged) in the format list.
* All 29 command numbers in the PulseCommand constset match the enum positions in src/pulsecore/native-common.h (ERROR 0 to SET_SOURCE_OUTPUT_MUTE 99).
* Argument layouts for every command are verified against protocol-native.c: volume, mute, default, port, card profile, move (index and name), subscribe, and get-info.
* Record decoders follow the upstream encoders field for field, with the same version gates: sink and source (proplist 13, base volume and card 15, ports 16, port availability 24, port group 34, formats 21 and 22), sink input and source output, card (profile availability 29, card ports 26, latency offset 27). The PA 16.1 fixtures decode with `at_end` checks.
* Bounds on the wire, apart from A2: `raw()`, `string()`, `arbitrary()`, `proplist()` (length check against the declared length), `channel_map()` and `cvolume()` (count at most CHANNELS_MAX), `frame.length` against MAX_PAYLOAD. The codec never reads past the packet.
* Gain semantics (src/pulse_volume.c3, src/volume.c3) match upstream. Raw 0x10000 is 1.0; amplitude is the cube of the slider (upstream pa_sw_volume_to_linear); dB is 20 log10 of amplitude, so 60 log10 of the slider (upstream pa_sw_volume_to_dB); 50 % gives -18.06 dB; `raw_from_gain` rounds like upstream `lround(cbrt(v) * VOLUME_NORM)` and clamps to VOLUME_MAX; NaN and zero map to mute. The balance rule and branches are upstream's (volume.c:691-713), and the one deliberate difference (no balance for a map with no left or right side) is documented.
* Subscription masks, device flags (HW_VOLUME_CTRL 0x1), port availability (0/1/2), and the event layout (SUBSCRIBE_EVENT with tag -1, event, index) match def.h and protocol-native.c. Events are coalesced: a burst of events costs one refresh (`events_seen` and `refresh_until_quiet`).
* Reconnect path: the mailbox fails queued commands with UNAVAILABLE during the outage (tested in the mock), and `Session.close` releases the socket, poller, wakeup and memory in order.
* Mailbox semantics (bleu_rt mailbox.c3): a partial drain leaves the wake-up signalled, so commands past the batch of 16 are not stranded. Checked by reading; the mock suite does not stress it.
* Operation ownership in `Audio.submit` (retain for the worker, release on the failure path) and in `execute_and_complete` is balanced.
* macOS HAL constants: all 27 match the generated bindings of objc2-core-audio 0.3.2 (see Tests), and the FourCC spellings agree with the names in the comments.
* macOS listener discipline: callbacks only post REFRESH (macos_coreaudio.c3:316-330), with no state and no user code, and listener removal happens on the worker. Property addresses use the right scopes and elements, and the per-device address count is within MAX_ADDRESSES (9 of 12).
* WASAPI COM: MTA entered once on the worker (`com::enter`), COM objects released on every path (`defer release_ref`), notifications unregistered before the enumerator is released and the apartment left, and the notification shell is created with one reference, registered, and released in the right order. QueryInterface answers only IUnknown, the shell's IID and IAgileObject, returning E_NOINTERFACE with a null out pointer (bleu_win com_shell.c3:77-90). add_ref and release use the previous-value semantics of Atomic and free at zero.
* Every vtable slot used by WASAPI matches the windows 0.58.0 bindings (see Tests). Callbacks post only.
* COM setting checks: `check_range` rejects out-of-range levels before any COM call, and unsupported commands return UNSUPPORTED rather than success.

## Tests run and results

1. `tests/run.sh mock`: 48 of 48 PASS, 0 FAIL, about 2 s. Matches the README.
2. `tests/run.sh real` against a PipeWire 1.0.5 pulse server started privately (pipewire and pipewire-pulse under a scratch XDG directory, null sink `bleu_test`, anonymous auth): 11 of 11 PASS, 0 FAIL. Both daemons were stopped afterwards.
3. `tests/run.sh real` against PulseAudio 16.1: NOT RE-RUN. The author's daemon (pid 6700) is alive but its native-protocol module failed at startup ("Failed to remove stale UNIX socket ... Permission denied"), so it has no socket. A second PulseAudio could not start: system mode refuses the scratch directory and the pid file belongs to pid 6700. Nothing was installed. The README's PA 16.1 rows are therefore unverified in this review.
4. `compile-test` of the library's dependency closure (run from a scratch directory, output outside the repo): 87 tests passed, 0 failed. Of these, 30 are `bleu::audio` (all pass). The library declares 30 `@test` functions; the README says 80.
5. `tools/check.sh bleu_core bleu_rt bleu_service bleu_win bleu_objc bleu_audio`: ok on all six targets (linux-x64, linux-aarch64, macos-aarch64, macos-x64, windows-x64, windows-aarch64).
