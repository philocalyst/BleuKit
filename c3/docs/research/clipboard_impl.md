(clipboard part, v1 cut). The README there is the coverage matrix; this file records what was
verified, where the implementation departs from the research or the brief, and what is open.

## Deviations from the research and the brief

1. Primary selection uses the data-control protocols (`primary_selection` events and
   `set_primary_selection`), not `wp-primary-selection`. The research prefers data-control for a
   clipboard manager because `zwp_primary_selection` set needs a serial and focus (WP-PRIM,
   single source; not re-checked here). The brief named wp-primary-selection; this is the
   deliberate change. On a wlroots compositor with data-control version 1 the primary selection
   is reported UNSUPPORTED_BACKEND.
2. Windows change detection polls `GetClipboardSequenceNumber` every 250 ms. The research and the
   brief asked for `WM_CLIPBOARDUPDATE` through `bleu::win::message_loop`, which does not route
   that message (read `bleu_win/src/message_loop.c3`). See "Changes needed in shared libraries".
3. The KDE hint is treated as a marker when the type is present, whatever its value. Klipper
   requires the value `secret`; the stricter reading keeps more content out of the history.
4. `Entry` has no `sensitive` field (flagged content is never stored, so it would always be false)
   and no source application (none of the three systems gives one portably in v1). The privacy
   state is on `Selection`.
5. The history keeps one text type per copy (the preferred one) and no other types. Fetch of other
   types reads the live owner for the current selection only.
6. Our own source echoes back as a selection event. The session recognises it by its type list
   and does not read it, so the board's owned copy and its history entry are not duplicated.
7. Serving our own source (`send`) and reading an offer are bounded by `transfer_timeout` on the
   worker. Reads are asynchronous (poll loop); writes to a requester are synchronous.

## Design points that a reviewer should check

* Board (`board.c3`) is neutral and pure: lanes and history, each with an arena; history bounded
  by count and bytes, oldest first; an identical copy moves to the top.
* Privacy: a marker means no bytes are read and no preview is made. The check is on the owner's
  types before any transfer starts.
* MIME names from other applications are validated and capped (`mime.c3`) before use.
* Previews are UTF-8 validated, control and bidi characters become spaces, and the text is cut on a
  character boundary at 512 bytes (`preview.c3`).
* A stopped worker fails every queued operation with UNAVAILABLE (`publish.c3`, `fail_pending`), so
  no caller waits for a worker that has gone.

## Changes needed in shared libraries (not made; they are read-only here)

* `bleu_win/src/message_loop.c3`: route `WM_CLIPBOARDUPDATE` (0x031D) to a new `EventKind`
  (`CLIPBOARD_UPDATE`), and add `AddClipboardFormatListener` / `RemoveClipboardFormatListener` externs.
  Then `windows_clipboard.c3` can drop the polling.
* `docs/C3_GOTCHAS.md`: the gotchas below should be appended by the lead. They were not appended
  here because this service may only write its own library and this file.

## Gotchas found while building this (for `C3_GOTCHAS.md`)

* A sub-module (`bleu::x::y`) must prefix functions and globals of its parent module, even when it
  imports the parent, e.g. `clipboard::ARENA_PAGE`. Types need no prefix.
* `@maydiscard` only applies to optional-returning functions.
* `@private` on a method is ignored; on a free function it limits visibility to its file.
* C3 0.8.5 has no free generic functions; use a generic module, or per-type code in a switch.
* An `extern fn` name is module-wide: two files of one module cannot both declare `sys_read`.
* `Obj.send` does not exist; objects are read with `send_id`, `send_bool`, `send_long`.
* A test that starts a scenario thread must attach the socket first: a receive on an unset
  descriptor fails with BACKEND_FAILURE, which looks like a protocol bug.
* A mock scenario must account for every request the client sends, including `destroy` of an
  object the client retires.
* `Operation{T}` results cannot use `Phase` for a generic module's enum; test completion with `wait(timeout)`.
